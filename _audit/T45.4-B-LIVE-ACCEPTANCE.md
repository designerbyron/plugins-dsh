## 0. Preparación

1. Crear el laboratorio vacío:

```powershell
$lab = "$env:USERPROFILE\lsc-lab-20261110-r2\home"
New-Item -ItemType Directory -Force -Path $lab | Out-Null
```

2. Arrancar DSH con ese `DSH_HOME` aislado. Instalar el plugin **por ruta local** desde Complementos → instalar desde ruta, apuntando a `C:\xampp\htdocs\plugins-dhs\lifecode-skill-center`, y encender «Habilitar» (la instalación desde UI no añade el bundle a `dsh.profile.bundles` hasta encenderlo). Reiniciar DSH.

3. Huella del perfil real **antes** (no debe cambiar en ningún momento):

```powershell
$real = "$env:USERPROFILE\.dsh"
foreach ($f in @("$real\lifecode-skill-center\center.json", "$real\lifecode-skill-center\knowledge.json")) {
  if (Test-Path $f) { "$f " + (Get-FileHash $f -Algorithm SHA256).Hash + " " + (Get-Item $f).Length }
}
Get-FileHash "$real\config.json" -Algorithm SHA256 -ErrorAction SilentlyContinue
```

4. Confirmar el candidato cargado:

```powershell

# o, en el panel, la versión visible debe ser 1.0.1
```

En la consola del renderer (DevTools):

```js

```

5. Anotar la URL del panel y el `center.json` del laboratorio:
   `$lab\lifecode-skill-center\center.json`.

## 1. Los 12 casos

Cada caso: pasos, observación esperada, evidencia y criterio. «PASS» exige la observación literal, no la intención.

### C1 — Abrir el cajón consulta una vez; inactividad no consulta
1. DevTools → Network, filtro `activity`.
2. Pulsar el botón de actividad del encabezado.
3. Esperar 60 s con el cajón abierto; cerrar; esperar 60 s más.

**Esperado:** exactamente **1** `GET /api/activity?limit=20` al abrir; **0** durante la inactividad; **0** al cerrar. Sin temporizadores propios.
**Evidencia:** captura de Network con las peticiones contadas.
**Criterio:** 1 / 0 / 0.

### C2 — Cerrar con × devuelve el foco al invocador
1. Con el teclado, tabular hasta el botón de actividad y activarlo con Enter.
2. Pulsar × (o Tab hasta «Cerrar actividad» + Enter).

**Esperado:** `document.activeElement` es el botón de actividad del encabezado (`aria-label` «Actividad de LifeCode»), no `BODY` ni un nodo interno del cajón.
**Evidencia:** en consola, `document.activeElement.outerHTML.slice(0,160)` antes y después.
**Criterio:** el foco vuelve al invocador.

### C3 — Cerrar con Escape devuelve el foco al invocador
1. Abrir con Enter desde el botón; pulsar Escape.

**Esperado:** igual que C2. Repetir 3 veces: el foco siempre vuelve al botón de actividad.
**Criterio:** 3/3.

### C4 — Crear una skill muestra un solo aviso de éxito
1. «Nueva skill», id `lab-acceptance-1`, guardar.

**Esperado:** un único aviso «Skill creada y evaluada.»; sin aviso de error; el aviso se puede cerrar; no se duplica.
**Evidencia:** captura del aviso y de `GET /api/activity` con el evento `skill.created`.
**Criterio:** 1 aviso, 0 errores.

### C5 — Crear un id duplicado muestra aviso persistente con el código real
1. «Nueva skill» con el id `lab-acceptance-1` (ya existe), guardar.

**Esperado:** un único aviso persistente de error cuyo detalle incluye el mensaje del Host y `code: exists` (o el código real devuelto); el mensaje inline del formulario sigue visible; no hay avisos duplicados; el envío no se repite solo.
**Evidencia:** captura del aviso y del inline; en Network, un solo `POST /api/state`.
**Criterio:** aviso con código + inline + un solo POST.

### C6 — Fila de actividad expandible
1. Abrir el cajón y pulsar una fila.

**Esperado:** la fila se expande (`aria-expanded="true"`), muestra resultado, versión, referencias, actor, evidencia y `correlationId` cuando existan.
**Evidencia:** captura expandida + atributo ARIA.
**Criterio:** expande y colapsa sin perder el foco del teclado.

### C7 — Paginación con ≥ 25 eventos
1. Crear 26 skills reales (panel o `POST /api/state` con `action:'create'` y payloads `{id:'lab-page-01'…'lab-page-26', description, body}`).
2. Abrir el cajón.

**Esperado:** primera página de 20 con «Cargar más»; al pulsarlo se añaden los siguientes sin duplicar y sin volver a pedir la primera página; `nextBefore` del servidor; al agotarse desaparece el botón.
**Evidencia:** Network (`limit=20`, después `before=…`), captura de la lista y del botón.
**Criterio:** 2 peticiones para 26 eventos, 0 duplicados.

### C8 — Indicador de no leídas
1. Abrir y cerrar el cajón (marca visto).
2. Crear una skill nueva desde el panel estando el cajón cerrado.

**Esperado:** aparece el punto de no leídas en el botón de actividad; al abrir el cajón desaparece y la marca se escribe una sola vez.
**Evidencia:** captura con punto, captura sin punto, Network del `seen` (una escritura).
**Criterio:** punto aparece y se limpia; 1 escritura de visto.

### C9 — Replay real por `operationId` desde una superficie soportada
1. En DevTools, ejecutar dos veces el mismo POST:

```js
const body = { action: 'create', payload: { id: 'lab-replay-1', description: 'Lab replay probe.', body: 'Probe para replay.', operationId: 'lab-op-replay-1' } };
const r1 = await (await fetch('/api/state', { method: 'POST', headers: { 'content-type': 'application/json' }, body: JSON.stringify(body) })).json();
const r2 = await (await fetch('/api/state', { method: 'POST', headers: { 'content-type': 'application/json' }, body: JSON.stringify(body) })).json();
({ first: r1, second: r2 });
```

**Esperado:** `r1.ok === true`; `r2.ok === true && r2.replayed === true && r2.activity === null`; en `center.json` hay **una** skill `lab-replay-1`; en el feed hay **un** evento con `operationId: 'lab-op-replay-1'` (no dos). Distinto de repetir sin `operationId`, que devuelve `ok:false, code:'exists'`.
**Evidencia:** consola con ambos JSON, recuento en el feed.
**Criterio:** replay idempotente y sin evento duplicado.

### C10 — Persistencia de `knowledge.json` con una operación real
1. Con el cajón cerrado, ejecutar un hallazgo real por la superficie de conocimiento:

```js
await (await fetch('/api/state', { method: 'POST', headers: { 'content-type': 'application/json' }, body: JSON.stringify({ action: 'insight', payload: { insightId: 'lab-insight-1', title: 'Hallazgo de laboratorio', summary: 'Prueba de persistencia de knowledge.json.', category: 'observation', confidence: 'moderate', evidence: [{ source: 'lab', location: 'lsc-lab-20261110-r2', verification: 'manual', result: 'escrito' }] } }) })).json();
```

2. Comprobar `$lab\lifecode-skill-center\knowledge.json` y abrir el cajón.

**Esperado:** el fichero existe y contiene `lab-insight-1`; el payload de actividad informa `sources` con `knowledge: ok`; hay un evento de conocimiento asociado.
**Evidencia:** hash/tamaño del fichero, captura del feed, JSON de `GET /api/activity`.
**Criterio:** fichero creado, fuente `ok`, evento visible.

### C11 — Reinicio completo de DSH
1. Cerrar DSH y volver a arrancarlo con el mismo `DSH_HOME` del laboratorio.
2. Abrir el panel.

**Esperado:** versión 1.0.1, `capabilities` contractVersion 2, `GET /api/activity` 200, actividad y skills anteriores intactas, foco (C2/C3) sigue funcionando.
**Evidencia:** captura del panel tras reinicio y `GET /api/capabilities`.
**Criterio:** sin pérdida de datos ni regresión de comportamiento.

### C12 — Integridad del paquete y datos, y perfil real intacto

**Evidencia:** hashes antes/después.
**Criterio:** perfil real byte a byte intacto.
